# Horizon Free Better v0.1.0-suplyox-lod.1

Custom Windows x64 client release for the Suplyox fork — November 7, 2026.

## Fixed

- Occlusion culling no longer calls `device.poll(PollType::Poll)` on every
  frame when no visibility readback is pending. Pending results still make
  progress. LOD and occlusion culling stay enabled; rendering detail is preserved.
- The Windows frame-pacing benchmark now uses the shared TCP/JSON control
  endpoint helper instead of a hardcoded Unix socket path.

## Added

- Separate timing spans for visibility readbacks, GPU polling, buffer unmapping,
  and draw regrouping to make future frame-time investigations more precise.
- A real-GPU regression test covering pending near-section and far-LOD results,
  idle frames without polling, and preservation of the previous visibility result.

## Measured results

Ryzen 7 7800X3D / RTX 3080 Ti, 1920×1080, render distance 8, LOD distance 64
with Full detail, simulation distance 16. A 192-block camera path at walking
speed ran for 45 seconds in three fresh worlds per version, in alternating
order. The requested 82 FPS limit was rounded to 80 by the game's ten-FPS
option steps. These are the medians across the three runs:

| Metric | Before | After |
|---|---:|---:|
| p99.9 frame time | 18.62 ms | 13.34 ms |
| Maximum frame time per run | 22.52 ms | 14.22 ms |
| 0.1% low FPS | 49.9 | 73.4 |

Average FPS stayed around 80. Across 135 measured seconds per version, frames
above 20 ms fell from 3 to 0. One baseline run was also smooth. This small
sample does not guarantee the same gains on every machine or scene. The
fixed-height offscreen camera path is not a full reproduction of grounded
walking or display/VSync behavior. Background LOD generation had reached
different completion levels at the start of the runs.

## Validation

- Three focused culling tests passed, including the real-GPU regression test.
- Clippy passed for all renderer targets with warnings treated as errors.
- rustfmt and `git diff --check` passed for the changed source.
- A direct Windows pacing smoke run passed using the TCP/JSON endpoint.
- The entire workspace and vanilla parity suite were not run.

## Windows x64 package

This is a **client update package for an existing Horizon installation**.
It does not contain a launcher, Minecraft JARs, or prepared game resources.
The included `horizon-client.exe` is built locally for Windows x86_64 MSVC
with the optimized `fast` profile; LTO is disabled.

Compatible resources prepared from your own Minecraft 26.3 installation are
required. The Microsoft Visual C++ 2015–2022 x64 runtime may also be needed.
Close the game and back up the existing client before replacing it with the
EXE from the ZIP. Keep your `.local/horizon-client/26.3` resources, settings,
and saved worlds. Compare the ZIP's SHA-256 with `SHA256SUMS.txt`.

Reproduce the build in PowerShell:

```powershell
$env:HORIZON_VERSION = '0.1.0-suplyox-lod.1'
cargo build --locked --profile fast -p horizon-client --bin horizon-client
```

This custom fork package is not an official upstream release and is not
digitally signed. The release includes build metadata and checksums.
